# 聊天口吻学习 · 首版实现

依据 `聊天口吻学习功能开发文档-v0.1.md` 实现，日期：2026-10-22。

## 使用

新增导入方式与识别服务配置详见[资料导入使用指南](./资料导入使用指南.md)。支持 TXT、CSV、HTML、JSON、短信 XML、iMessage 明文数据库、文字 PDF；聊天截图和扫描 PDF 使用独立配置的识别服务，点击发送后才上传。

1. 打开聊天右上角 `···`，在人设与背景之间点击 **学习 TA 的说话方式 → 导入聊天记录**。
2. 粘贴文本或选择资料文件。转换、识别后先核对原文，再将发言者分别标记为“我”“学习对象”“不参与”；同一人的多个昵称可以选择相同身份，单人帖子只需指定学习对象。
3. 勾选参与分析的消息，确认实际提交的样本。原文可先脱敏再重新解析。
4. 在已配置 AI 的情况下点击 **开始学习**。这一步才会发送样本；没有 AI 也可以完成本地解析与预览。
5. 直接试聊体验回复，也可填写“希望 TA 怎么回应你？”提供具体调整；学习分析、规则与证据编号仅供内部使用。
6. 点击 **就这样，开始聊天** 后，从下一次请求生效。标题旁的学习口吻标签也可打开档案。

在已应用档案中可启停、补充记录、更换对象、回退一次或删除本地学习资料。“删除学习资料”同时删除当前与回退档案。试聊和草稿不进入正式聊天。

## 保存与限制

- 每次开始学习时按固定 12 项检查表达习惯，有依据才写入。每条保存具体触发条件、回应方式、原句引用、证据强度和适用边界。清单之外可保存最多 3 条跨独立对话重复出现且会影响回复的观察。
- 学习时先统计未截断样本的长短、句末标点和条内换行，再用 12 项观察判断这些习惯在哪些场景适用。回复时沿用当前角色设定，只在当前消息与证据的触发消息相近时带入最多两条原句供参考。简单确认、告别和已答清的问题可以直接收尾。
- 样本区分单条消息内换行和原记录中相邻的两条消息。同一次连发只计作一次场景。仅在触发消息和回应均有有效且顺序合理的时间戳时分析间隔。试聊和正式回复按输入内容、话题数和情绪参考已学到的节奏。
- 补充记录时，用新样本修正观察，仍有已保存证据且未被新样本修正的观察会保留。旧档案可继续使用，通过补充记录或重新学习生成新的结构化观察。模型遵循程度需要实际试聊。提示中的行为要求参见[聊天记录学习与回复行为准则skill.md](./聊天记录学习与回复行为准则skill.md)。

- 每个角色单独保存基础人设、当前口吻档案和一个回退版本；自定义角色刷新后恢复。
- 新记录使用浏览器键 `xinyu_characters_v1`，带 `schemaVersion: 1`。旧人设与昵称在首次使用时迁移，旧背景与外观键保留。
- 完整原文仅在导入流程内存中使用；关闭流程释放。保留的是已应用档案、最多 200 条有限证据、最多 6 个示例和最近 10 次批次摘要。
- 单文件上限 20 MB，PDF 最多 20 页；转换后文字上限 2 MB / 10,000 条消息。分析样本 JSON 上限 30,000 字符，按前中后均匀选取并显示截断标记。单档案上限 256 KB，实际浏览器剩余容量不足时保存失败并保留原档案。
- 同一批次有时间的重复消息去重；无时间的重复短句提示但保留。补充时只能比对此前保留的有限证据，不能检测此前未保存的整份原文。
- 资料仅保存在当前浏览器与访问地址，正式聊天历史不持久化。离线回复明确标为预设内容。

## 验证

Node 可直接执行逻辑测试：

```text
node demo/tests/style-learning.cjs
```

浏览器测试需已安装的 Edge，以及可通过 `NODE_PATH` 找到的 Playwright：

```text
node demo/tests/style-learning-browser.cjs
node demo/tests/navigation.cjs
```

学习流程测试使用模拟 AI，不读取用户浏览器配置，不向真实服务发送聊天记录。覆盖解析、昵称合并、筛选、预算、模型校验、草稿与试聊隔离、角色隔离、取消与迟到结果、保存失败、补充／更换／回退／删除、刷新恢复、状态关怀和手机流程。原有测试继续覆盖导航、主题及背景保留。

真实模型的风格相似度未自动评估：需要按开发文档第 9.2 节，用获得许可的样本连接实际服务试聊并人工评分。当前不宣称达到五分制 4 分或任何还原度百分比。
