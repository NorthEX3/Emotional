# 心语｜资料导入使用指南

更新：2026-11-05

## 入口与共同流程

打开 `index.html`，强制刷新页面。进入一个角色的聊天，点击右上角 `···` → **学习 TA 的说话方式** → **导入聊天记录**。已有档案可以选择“补充记录”或“更换对象”。

1. 选择文件。文本类文件先在本地转换，转换后内容显示在上方文本框。
2. 核对文字；有缺漏、发言者错误或换行问题时，先修改文本，再点击“解析并预览”。
3. 将发言者标记为“学习对象”“我”或“不参与”。社交帖子只有一位作者时，只指定学习对象即可。
4. 勾选要采用的消息，点击“确认选择，预览实际提交样本”。
5. 确认后点击“开始学习”。这时才将选中的文字发送给聊天设置中的 AI 服务。
6. 查看档案、填写“我的修正”、试聊，最后点击“应用到此角色”。

单文件最多 20 MB；转换后的文字最多 2 MB、10,000 条记录；PDF 最多 20 页。超过时请先拆分。不同导出工具的格式不统一，以下是实际适配范围，不代表能读取所有同名文件。

## 各类资料如何导入

| 来源 | 文件与要求 | 操作 |
|---|---|---|
| 手工整理、微信/iMessage 的文字导出 | UTF-8 TXT，格式为 `发言者：正文`，可以带日期时间 | 直接选择文件或粘贴原文 |
| 微信或 iMessage CSV 导出 | 表头含发言者与正文；支持 `sender/content`、`发送人/内容`、`from/message`、`NickName/Message` 等字段 | 选择 CSV，核对识别出的发言者 |
| 微信 HTML 导出 | 每条有 `.sender` 或 `.sender-name`，正文为 `.content` 或 `.message-text` | 选择 HTML；不匹配时改为 TXT/CSV 导出 |
| Android SMS Backup & Restore | XML 中有 `<sms address="…" type="1" body="…"/>`；type=2 作为“我” | 选择 XML，再按联系人标记学习对象 |
| 社交媒体、通用聊天 JSON | 数组，或 `messages/statuses/posts/weibos/data/notes` 数组；正文可为 `text/content/desc/caption` 等 | 选择 JSON；没有作者字段时先填写“无作者字段的帖子作者” |
| 微博、小红书等 JSON | 识别 `user.screen_name/name/nickname`、标题和正文 | 核对作者，排除转发、引用和非本人文字 |
| Instagram JSON | 识别 `media[0].title/caption` 或记录的 `title/caption` | 通常需要先填写帖子作者，再选择文件 |
| iMessage 数据库副本 | 上传你自行导出的 `chat.db` 或 `.sqlite`；需要有 message、handle 表及明文 text 字段 | 在本地读取，按联系人号码/地址选择对象；不会直接访问 Mac 的数据库 |
| 文字 PDF | 有可复制的文字层，最多 20 页 | 选择 PDF，先本地提取；版面混乱时可用下述识别服务 |
| 聊天截图、扫描 PDF | PNG/JPG/JPEG/WebP 或 PDF | 配置识别服务并点击发送，见下一节 |

CSV 支持引号包裹的逗号和多行正文。结构化文件转换后主要保留发言者和正文；除数据库按原时间排序外，不利用导出时间判断消息节奏。请勿据此推断连续发送多条消息的习惯。

iMessage 副本如果只有 `attributedBody`、没有明文 `text`，请用原导出工具转成 TXT/CSV。本应用不读取加密微信数据库，不会绕过操作系统权限。导出的独立数据库副本应包含已提交的数据，单独复制正在写入的 chat.db 可能遗漏 WAL 中的记录。

无作者字段时填写的名字是你的声明，不是系统识别出的身份。单人帖子只能提供该作者的表达证据；没有对话上下文时不能推断其安慰、追问等互动行为。

## 截图和扫描 PDF 的识别服务

选择图片后，文件卡片会显示缩略图、名称、大小及“尚未发送”。这表示文件已经在本地选中，还没有上传。点击发送后状态变为请求处理中；只有拿到文字结果并填入原文框后，才显示“识别完成”。识别失败会显示原因并允许重试。

识别服务设置中可以点击“使用聊天的 API 地址和密钥”。如果聊天地址为 DeepSeek 官方地址，会同时填入 `deepseek-flash`；其他服务需要自行确认图片模型。发送识别按钮始终位于设置区域上方，不必滚动寻找。

识别服务与聊天模型分别配置。需要一个**支持图片输入、兼容 OpenAI Chat Completions 格式**的服务。

1. 展开“截图／扫描 PDF 识别服务”。
2. 填写 API 基础地址、支持图片的模型名称和 API Key。地址填写服务商给出的基础路径，例如 `https://你的服务/v1`，不要填完整的 `/chat/completions` 路径。
3. 选择图片或 PDF。图片选中后不会自动发送；PDF 默认只在本地提取文字。
4. 点击“将选中图片／PDF 发送至识别服务”。选中的文件图片或 PDF 页面会发往你填写的识别服务；每页 PDF 一次请求，可能产生费用。
5. 等待文字显示，核对后再解析、选择学习对象和开始学习。

普通照片没有聊天文字时，不会转换成口吻样本。照片 EXIF 时间线、人物性格、关系和共同经历不进入本次学习。

没有昵称的截图，识别结果会用“左侧”“右侧”作为发言者。必须由你确认哪边是学习对象；“待确认”或模糊、遮挡的内容建议排除。跨页 PDF 可能重复上一页的聊天片段，请在预览时移除重复消息。

可以点击“取消本次请求”或关闭弹窗停止后续识别；已经发出的请求仍可能被服务端处理。识别失败或取消不会覆盖已应用的口吻档案。

填写后点击“保存识别设置”，或发起一次识别，API 地址、模型和密钥会一起保存在当前浏览器与访问地址中；关闭弹窗、刷新后自动恢复。点击“清除识别设置”可删除。不要把密钥粘贴进聊天原文。识别服务与聊天服务必须允许浏览器跨域访问；网络失败时先检查地址、密钥、模型是否支持图片及服务的跨域设置。

## 常见问题

- **JSON/CSV 没有作者**：先填写帖子作者，再重新选择文件。不能确认作者的内容不要用于学习。
- **HTML 无法识别结构**：换用 TXT/CSV，或把正文整理成示例格式后粘贴；网页脚本不会执行。
- **PDF 提取后顺序错乱**：使用识别服务，或手工调整文字后重新解析。
- **截图识别出来不像原文**：修改识别结果，避免让模糊文字变成口吻证据。
- **模型识别接口报 400/404**：检查基础地址及模型名，并确认模型支持图片输入。
- **重新导入后旧档案是否丢失**：导入、识别和分析都是草稿，点击应用后才替换旧档案。

## 实现与验证范围

本应用将 ex-skill 的资料读取思路适配为浏览器本地解析，复用已有的样本预览与角色隔离流程。原项目 Python 脚本保留在 `third_party/ex-skill-main/`，不会在网页里直接执行。

PDF.js 5.6.205（Apache-2.0）和 sql.js 1.13.0（MIT）随应用本地提供；许可见 `vendor/`。PDF.js 构建被包装为浏览器脚本，以支持本地文件页面，原版权信息保留。

自动测试使用虚构文件与模拟识别服务，覆盖 CSV/JSON/HTML/XML、PDF 文字读取、SQLite、图片与 PDF 的确认发送、配置保存、恢复、清除及桌面/手机布局。真实识别服务的准确率和不同平台导出变体需用实际资料核对。
